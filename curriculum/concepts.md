# Concept ledger

**Purpose.** A lookup table of what the learner knows at each task, so every snippet the tutor shows is readable with what has already been taught (pretesting only works when the gap is the one construct being taught, not three unknown ones).
**Rule.** Every snippet the learner reads (probe, runner, stub doc, lesson example, hint) may use only constructs introduced at or before the current task, plus the one construct being taught. When showing a behaviour needs something not yet introduced, restructure with known tools ("bridges"). Escape hatches, labelled in the snippet: preview (a later construct shown in passing, one-line comment, never quizzed) and harness (code the learner can treat as a black box: `tasks::lab::kata(..)`, `show!`).
**How the tutor uses it.** Before showing a snippet, every construct must appear in the ledger at or before the current task, or be labelled preview/harness.
**Scope.** 83 task rows (S1-T1 … S17-T3). Gates are excluded: a gate may use everything up to its stage. A construct appears once, at its first teaching point; later rows only add what is new.
**Sections.** 1 Ledger · 2 Bridges · 3 Previews · 4 Harness · 5 Snippet rules. Specs in `curriculum/stage-*.md` win on *what* is taught; this file fixes *when* it may appear in a snippet.

## 1. Ledger

Phase I is granular (a probe is one row cell); from Stage 5 on, rows name families and crates. "Named" means the construct is mentioned as banned or as a contrast, not used.

## 2. Bridges

How to show a behaviour before the idiomatic tool exists. "Earliest" is the first task where the bridge itself is fully in the ledger. Verified on Rust 1.89 where marked.

| # | Behaviour to show | Earliest | Bridge with known tools | Forbidden shortcut → unlocked at |
|---|---|---|---|---|
| 1 | Runtime integer overflow: debug panics, release wraps | S1-T1 | `fn add(a: u8, b: u8) -> u8 { a + b }` then `println!("{}", add(200, 100));`. The `arithmetic_overflow` lint only sees constants inside one body; a parameter is opaque. Verified 1.89: debug `attempt to add with overflow`, `--release` prints `44`. ## 5. Snippet rules

Cognitive-load rules for every snippet the tutor shows (probe, hint rung 3, lesson example):

| Rule | Detail |
|---|---|
| One new construct | Exactly one construct being taught per probe; everything else is in the ledger at or before the task. A twist re-uses the same snippet with one line changed. |
| ≤ 12 lines | A complete `fn main`, rustfmt style, no `use` lines except std paths already in the ledger. Names short and literal (`a`, `b`, `total`), no kata function names. |
| Naive before idiomatic | For an idiom bullet the snippet holds `// naive` first, then `// idiomatic`, both printing the same thing; the prediction asks which is wrong and on what input, or what each prints. (Worked-example fading: the learner's likely first draft is the anchor.) |
| ≤ 2 previews | At most two `// preview:` lines per snippet, each one construct, never the subject of the question. |
| Surprising output | Prefer outputs an engineer from another language gets wrong: wrap vs panic, `if` as a value, shadowing changing type, `String` moved vs `i32` copied, byte length vs char count, `HashMap` order changing between runs, `0.1 + 0.2`, drop order, `select!` dropping a branch. (Pretesting: the gap must be felt before it is explained.) |
| Phase I asks why, never codes | Stages 1-4: "which line does the compiler reject, and why?" is allowed; error codes and "write failing code" are not. From S5-T1 the gap may name the code. |
| Deterministic unless that is the lesson | No `HashMap` iteration, clocks, randomness or thread timing in a printed result, except in the probe whose point is that nondeterminism (S2-T1, S7-T1). |
| Prediction first | One prediction question as the last line; no answer before a committed guess; `hint` during a probe is a narrowing question, never the answer. (Retrieval and Socratic prompting, not explanation.) |
| Leave it green | After the gap, `probe.rs` compiles, is formatted and clippy-clean; a rejected line becomes the fixed line or `// rejected: <why>`. |
| Runtime values come from the ledger | To stop constant folding use Bridge 1 (a fn parameter) or Bridge 2 (`parse` / `env::args`); `black_box` only from S6-T5. |
| Profile is explicit | When the point is debug vs release, the probe says `scripts/run.sh probe --release` and the snippet is run both ways. |
